## Маршруты и данные

- `/`: серверный каталог с поиском, выбором лицензии и фильтром наличия версий.
  Первой идёт библиотека с наибольшим известным числом звёзд GitHub. Пакеты без
  сведений о звёздах идут в конце. При вводе запроса можно выбрать релевантность.
  Она учитывает точное имя, начало и фрагмент имени, близость и частоту слов в описании.
  После поиска можно прокрутить страницу обратно к RADAR. Все параметры и cursor
  находятся в URL. Каждый активный фильтр можно снять отдельно. После изменения
  фильтра выдача начинается с первой страницы и сохраняет сортировку и размер страницы.
  По умолчанию выводятся 12 записей. Поле GraphQL `catalogLicenses` возвращает
  распознанные лицензии загруженных пакетов PyPI. MIT и MIT License доступны одним
  пунктом. Составные выражения SPDX сохраняются целиком.
  Первый экран и форма поиска отдаются до ответа каталога. Результаты и варианты лицензий
  приходят отдельными частями HTML. Каждая строка показывает версию один раз. Ошибки
  обновления видны в выдаче, даты наблюдений и задержка проекции доступны в карточке.
  Операция `PublicCatalog` возвращает также публичную ревизию справочника. Изменение
  нормализованной лицензии или принадлежности пакета к PyPI обновляет ревизию в той же
  транзакции. Каждый процесс Next.js хранит один полный список по этой ревизии.
  Параллельные чтения используют общий запрос. После ошибки следующее чтение повторяет загрузку.
- `/packages/[name]`: метаданные, до 5 репозиториев с явной отметкой ограничения,
  страницы по 20 версий и requirements, выбор версии, OSV и aliases.
  Для HTML-заголовка операция `PackageMetadata` читает имя, описание и источник.
  Подробности OSV и объявленные зависимости запрашиваются для отображаемого релиза.
  Если карточка открыта из результатов поиска, ссылка «К результатам поиска»
  возвращает на исходную страницу даже после выбора другой версии и перезагрузки.
  Показаны только загруженные версии, не обещается полная история PyPI.
- `/compare?packages=a,b,c,d`: сравнение до четырёх пакетов. URL самодостаточен;
  список выбора сохраняется в localStorage, при недоступном хранилище — в памяти вкладки.
  Для двух–четырёх пакетов режим «Только различия» скрывает совпадающие строки.
  Параметр `differences=1` сохраняет режим в ссылке. Кнопка «Скопировать ссылку»
  передаёт адрес в буфер обмена или показывает его для ручного копирования.
- `/demo`: сохранённая техническая демонстрация query/mutation/subscription этапа 0.

Публичные маршруты показывают только `source=PYPI`, включая версии. Синтетические
записи этапа 2 сохранены для прежних проверок, но скрыты на публичных страницах.
Операции именованные, переменные и типы генерируются Codegen. SSR обращается
только к общему GraphQL gateway. Браузер не обращается к внешним источникам или БД.

Canonical строится по `SITE_URL`; без него используется localhost и `noindex`.
Поисковые варианты и сравнение всегда `noindex`. Варианты версии имеют canonical
базовой страницы пакета. Настройка origin не публикует сайт и не меняет loopback bind.

## Сортировка всего набора

Catalog владеет полями `github_stars`, `github_checked_at`, `github_projected_at`,
`github_status` в собственной таблице пакетов (миграция `catalog_0004`).
Звёзды — максимум среди подтверждённых связей с GitHub, а не сумма репозиториев.
Неизвестное значение хранится как NULL, сортируется после нуля.

SQL сортирует весь отфильтрованный набор по `coalesce(github_stars,-1) DESC, id ASC`.
Cursor включает значение stars и уникальный ID, связан с поиском, фильтрами и сортировкой.
Индекс соответствует порядку. Это keyset-пагинация изменяемого набора, не снимок
транзакции на весь просмотр: при изменении stars между запросами возможны сдвиги.

Repositories после commit сохраняет checkpoint и вызывает защищённую GraphQL mutation
Catalog. Повтор после неудачной публикации использует checkpoint без повторного GitHub
HTTP-запроса. Catalog применяет только более новый timestamp; одинаковые и старые
сообщения не меняют данные или время применения. Доступ требует внутренний admin token.

Celery Beat раз в 60 секунд запускает сверку очередных 100 публичных пакетов.
Catalog получает снимки через защищённый GraphQL Repositories; чужая БД не читается.
Cursor сверки хранится в Catalog, advisory lock запрещает одновременный проход.
Полный цикл занимает примерно `ceil(N/100)` минут без очередей и сбоев, а не 60 секунд
для любого объёма. Снимок учитывает timestamp самого репозитория: изменение общего
репозитория через другой пакет также попадёт в проекцию.

`checkedAt` — время состояния источника/последнего изменения связанного репозитория,
`projectedAt` — время применения в Catalog, `lagSeconds` — неотрицательная разность
этих времён. UI показывает дату и задержку проекции; это не гарантия текущего состояния
GitHub и не обещание верхней границы задержки во время сбоя.

## Состояния и внешний вид

Стиль MDOW: графит, белый текст, оранжевые рамки и углы, без скруглений.
Каталог, карточка и сравнение поддерживают пустые результаты, loading, ошибочный
cursor, отсутствующий пакет, ошибку источника и последний сохранённый результат.
Сбой Security или Repositories не скрывает доступную часть страницы.
Отсутствие OSV-находок не названо гарантией безопасности; requirements показаны
как объявленные условия, не разрешённое дерево установленного окружения.

Есть подписи полей, skip link, видимый focus, управление клавиатурой,
мобильная компоновка; широкая таблица сравнения прокручивается внутри области.
Общая шапка, навигация и цель skip link находятся в корневом layout,
поэтому страницы и потоковый loading не создают повторяющихся ID.

## Проверки

`uv run python -m scripts.verify_stage4` временно останавливает импортёры и Beat,
создаёт явно подписанные UI-fixtures, проверяет PostgreSQL/GraphQL и Playwright,
последовательно останавливает Security, Repositories и Catalog для браузерных
fault-проверок. `finally` удаляет тестовые записи и восстанавливает сервисы.
Проверки не используют живые API. Метки PYPI/GITHUB/OSV у этих временных записей
имитируют результат адаптеров; это не реальные данные и не доказательство импорта.

Команда требует установленный Chromium (`pnpm exec playwright install chromium`),
запущенный Compose и актуальные образы `checks`, backend и `web`.
Обычный `pnpm test:e2e` включает сценарии этапа 4 и требует подготовленных fixtures;
для полного воспроизводимого запуска используйте orchestration-команду выше.

Массовый импорт, нагрузочные измерения, личный кабинет и публикация относятся
к следующим этапам. Текущий сайт работает на небольшой реальной выборке этапа 3.
