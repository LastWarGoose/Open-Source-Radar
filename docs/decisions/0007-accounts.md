# Локальные аккаунты и персональные функции

Пользователь выбрал логин/пароль и одноразовый код восстановления без почты.
Workspace владеет аккаунтами, сессиями, подборками, отслеживанием и уведомлениями.
Прикладные операции проходят через GraphQL gateway; прямого доступа сайта к БД нет.

## Подборки и действия с пакетами

В каталоге и карточке пакета кнопки отслеживания и добавления в подборку стоят
рядом со сравнением. После входа Workspace возвращает статус отслеживания для
пакетов текущей страницы одним запросом владельца (до 100 ID). Список подборок
загружается при открытии окна выбора. В кабинете кнопка «Создать подборку»
открывает окно ввода названия. Нажатие на название раскрывает содержимое,
повторное нажатие, клик снаружи или Escape закрывает его. Кнопка удаления
доступна через «Действия» внутри раскрытой подборки.

## Вход и восстановление

Логин нормализуется в нижний регистр: 3–40 латинских букв, цифр, `_` и `-`.
Пароль: 12–128 символов; `pwdlib[argon2] 0.3.0`, Argon2id через
`PasswordHash.recommended()`. [Официальный пример FastAPI](https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/).
Случайная сессия содержит 256 бит; в PostgreSQL хранится SHA-256 токена и срок
жизни 7 дней. Cookie `radar_session`: HttpOnly, SameSite=Strict, Path=/,
Secure при HTTPS `SITE_URL`. Для локального HTTP Secure выключен.

Код восстановления содержит 256 бит случайности, хранится только его SHA-256.
Регистрация показывает код один раз. Восстановление атомарно меняет пароль и код,
отзывает все сессии. Без пароля и сохранённого кода самостоятельное восстановление
невозможно; email и SMS отсутствуют. Смена роли не требует выпуска нового токена:
роль читается из текущего аккаунта при проверке доступа.

Регистрация всегда выдаёт `user`. Администратор назначается локальным оператором
после регистрации аккаунта:

```sh
docker compose exec workspace .venv/bin/python -m scripts.account_role ИМЯ admin
```

Для снятия роли заменить `admin` на `user`. Общего пароля/аккаунта по умолчанию нет.
`DEV_ADMIN_TOKEN` остаётся служебным credential для workers, CLI и прежних тестов;
он не выдаётся браузеру. Его владелец имеет административные полномочия.

При входе и восстановлении допускается 10 попыток на логин за 15 минут,
общий предел — 300 за 15 минут; регистраций — 50 за 15 минут на установку.
Счётчики атомарные в PostgreSQL; это начальная защита, не распределённая anti-abuse
система. Общие лимиты GraphQL и наблюдаемость относятся к этапу 7.

Workspace выполняет регистрацию, вход и восстановление в отдельном пуле из четырёх
потоков на процесс. При входе сервис читает сохранённый хеш и возвращает соединение
PostgreSQL в пул до проверки Argon2id. Перед созданием сессии он блокирует строку
аккаунта и сверяет хеш ещё раз. Если за это время пользователь восстановил доступ,
проверка старого пароля уже не выдаст сессию. Если сессия успела появиться первой,
восстановление отзовёт её в своей транзакции.

Для чтения подборок и сессии доступны отдельные от вычисления паролей потоки.
Запрос `me` использует аккаунт, который Workspace проверил по cookie при создании
контекста этого GraphQL-запроса.

## Доступ и транспорт

Изменения требуют POST и разрешённый Origin, включая вход/восстановление.
Gateway передаёт cookie/Origin и Set-Cookie; CORS разрешает credentials только
локальным адресам и настроенному SITE_URL. Передача заголовков соответствует
[документации Hive](https://the-guild.dev/graphql/hive/docs/gateway/other-features/header-propagation).
Пользовательские ID и роли из произвольных заголовков не принимаются.
Ответы gateway — `no-store, private`. Приватные страницы не индексируются,
личные данные загружаются в браузере; публичный SSR не получает сессионную cookie.
После входа/выхода Apollo store очищается, документ перезагружается, WebSocket закрывается.

Workspace фильтрует каждое чтение/изменение по владельцу; вложенные списки также
проверяют владельца. Catalog запрашивает текущую сессию через GraphQL Workspace
для каждой административной операции. При недоступности Workspace доступ закрыт.
Подписка `importProgress` читает PostgreSQL сразу и затем раз в секунду, повторно
проверяя сессию и роль; отзыв/истечение прекращают поток. UI дополнительно читает
job каждые 3 секунды и после события, поэтому обрыв соединения не теряет состояние.
Это polling внутри subscription, не система долговечной доставки событий Redis.

## Отслеживание и уведомления

Подборки и их элементы, отслеживание и чтение уведомлений идемпотентны.
Списки имеют cursor-пагинацию, максимум 100; UI показывает страницы по 20.
Начало отслеживания фиксирует текущую версию из Catalog через GraphQL.
После успешного обычного импорта Catalog отправляет Workspace номер версии и время.
Если номер изменился, создаётся сохранённое уведомление каждому подписчику.
Устаревшие события игнорируются; повтор события не создаёт дублей. Доставка входит
в checkpoint/retry существующего задания импорта. Исторические импорты версий
не создают уведомлений об обновлении. Ошибки Workspace не откатывают сохранённые
метаданные PyPI, но оставляют задание для ограниченного повтора.

На этом этапе обновления поступают при запуске импорта администратором/CLI.
Отслеживание само по себе не запускает внешние HTTP-запросы и не обещает суточный
мониторинг PyPI. Периодический обход отслеживаемых пакетов требует отдельной
политики расписания в пределах квот. Email/push не реализуются.

## Проверки

`uv run python -m scripts.verify_stage6` останавливает только ранее работавшие
сборщики/Beat, проверяет API и браузер на отдельных аккаунтах, удаляет только свои
fixtures и восстанавливает сборщики. Внешние API не вызываются. Трассировка видео
и Playwright trace для форм входа выключена, чтобы не сохранять пароли и коды.
Скриншоты снимаются только после закрытия экрана кода восстановления.
