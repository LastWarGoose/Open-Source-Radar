# Наблюдаемость и эксплуатация локального стенда

Базовый запуск применяет ограничения GraphQL. Для сбора телеметрии запустите профиль из корня репозитория.

```sh
docker compose -f compose.yaml -f compose.observability.yaml --profile observability up -d --build --wait
```

[Дашборд Open Source Radar](http://localhost:3001/d/open-source-radar/open-source-radar) показывает задержки, ошибки GraphQL, активные подписки, решения шлюза, возраст очередей, попытки, квоты и свежесть каждого источника. Grafana, Prometheus, Tempo, Loki и OTLP Collector работают в локальном образе LGTM. Grafana доступна на loopback в режиме просмотра. Правила Prometheus отслеживают потерю метрик, очередь старше часа, давно не обновлявшийся источник, превышение доли ошибок и задержку каталога. Состояние правил доступно в Grafana. Внешний получатель уведомлений не настроен.

## Поиск причины ошибки

В панели Network браузера откройте GraphQL-ответ и скопируйте `x-trace-id`. В Grafana Explore выберите Tempo и поиск по Trace ID. Для коррелированных записей выберите Loki и запрос `{service_name=~".+"} | trace_id="<ID>"`. Для HTTP клиент и SSR передают W3C trace context. Шлюз измеряет операции, включая ответы HTTP 200 с GraphQL errors. Для известных операций используется фиксированный набор имён, остальные попадают в группу `other`.

Штатная выборка составляет около 10% трасс. Счётчики и гистограммы охватывают все исполняемые операции. Источники отдают агрегированные метрики из собственных баз. SQL сборщика запускается раз в 15 секунд. После фиксации задания в PostgreSQL его контекст сохраняется в outbox или source_work и передаётся в заголовках Celery. Для трасс используются фиксированные имена операций и сервисов. Тела запросов, переменные, cookies и тексты исключений в экспорт не включаются.

## Бюджеты шлюза

Глубина ограничена 16 уровнями, документ — 6 000 токенов, операция — 32 псевдонимами. Расчёт стоимости учитывает актуальные переменные, фрагменты, директивы и размеры вложенных списков. Бюджет — 100 000 единиц. Размер сериализованных переменных HTTP-операции ограничен 4 МиБ. Штатные запросы проверки схемы и сравнения четырёх пакетов входят в эти пределы.

За секунду один экземпляр шлюза допускает до 200 операций суммарно, до 100 от одного сетевого адреса и до 40 по одной cookie сессии. Административные операции постановки заданий ограничены 30 в минуту с адреса. Активных подписок — до 128 на экземпляр и до 32 с адреса. При отказе клиент получает GraphQL error с кодом краткой причины. Для развёртывания нескольких шлюзов нужен общий счётчик или распределение бюджета между репликами.

## Данные и резервная копия

Команда `backup` сохраняет четыре архива PostgreSQL и контрольные суммы в новый каталог. Архив Workspace содержит закрытые данные. Держите каталог копий вне Git с ограниченным доступом. Отдельные базы снимаются последовательно. Для восстановления на выбранный момент времени потребуется политика WAL и внешнее хранилище.

```sh
uv run python -m scripts.backup backup open-source-radar .runtime/backup-001
docker compose -p radar-stage7-check up -d --wait postgres
uv run python -m scripts.backup restore radar-stage7-check .runtime/backup-001
```

Восстановление проверяет контрольные суммы и наличие пустых целевых баз. Владелец каждой базы восстанавливает свой архив в транзакции. Выбирайте новый проект для следующего восстановления. Приложение и миграции запускайте после восстановления всех четырёх баз.

### Повтор испытаний на копии

После восстановления запустите отдельный проект. Для него используются собственные volumes и порты 3300, 4400 и 3301. Внешняя сеть сборщиков закрыта.

```sh
docker compose -p radar-stage7-check -f compose.yaml -f compose.observability.yaml -f compose.stage7-test.yaml --profile observability up -d --build --wait
docker compose -p radar-stage7-check -f compose.yaml -f compose.observability.yaml -f compose.stage7-test.yaml build checks
docker compose -p radar-stage7-check -f compose.yaml -f compose.observability.yaml -f compose.stage7-test.yaml run --rm --no-deps -e RADAR_STAGE7_FIXTURES=1 checks .venv/bin/python -m scripts.check_stage7
uv run python -m scripts.verify_tracing http://localhost:4400/graphql http://localhost:3301
uv run python -m scripts.fault_stage7
uv run python -m scripts.load_stage7 warm baseline
```

Нагрузочный сценарий создаёт 20 временных пользователей и проверяет содержимое личной подборки каждого. Во время прогона открыта подписка на изменение статуса задания. Скрипт сохраняет сводки k6 и время доставки завершающего события в `.runtime`. Рабочие архивы и пароли в отчёт не входят. После испытаний тестовый проект можно остановить с теми же файлами Compose и командой `stop`.

## Поиск и периодическое обновление

По умолчанию сайт показывает точное нормализованное имя, затем совпадения по началу имени, остальной части имени и описанию. Внутри группы порядок устойчив по ID, курсор хранит группу и последний ID. Явная сортировка пользователя сохраняется в URL.

Каждые 15 минут Beat может запланировать обновление двух разных пакетов из наблюдений. Workspace возвращает только идентификаторы через защищённую внутреннюю GraphQL-операцию. Catalog отбирает реальные пакеты и использует существующий импорт PyPI с последующим обогащением GitHub и OSV. Курсор обхода и идентификатор цикла сохранены в PostgreSQL. Повтор после сбоя использует прежний ключ задания. Следующий полный обход начинается через сутки после завершения предыдущего. При пустом списке проверка повторяется через 15 минут.
