# Ревью

1. Сверь критерии, diff и отчёт QA для одной версии. Проследи изменённый путь от действия пользователя до результата. Учти заключение по безопасности, если оно относится к задаче.
2. Для каждого блокирующего замечания укажи ID, файл или операцию, наблюдаемый эффект, владельца исправления и условие закрытия. Отдели предложения на будущее от дефектов текущей задачи.
3. Верни архитектору одно решение: «принято», «на исправление» или «проверка заблокирована» с причиной. После исправления сверь новый diff и повторную проверку QA по тем же ID. Код исправляет владелец.
